## API access from this machine

The scripts talk to the RPC endpoints of the official client (`POST
https://www.kaggle.com/api/v1/<service>/<method>`) with `requests` only (no `kaggle` package
needed). Credentials: `KAGGLE_USERNAME` + `KAGGLE_KEY`, else `~/.kaggle/kaggle.json`, else a
dummy header that the cloud session's network proxy replaces with the user's key. The
official CLI 2.x defaults to `api.kaggle.com`, which the proxy does not authenticate; it is
not used. File uploads go to `www.googleapis.com` (GCS resumable upload, about 55 MB/s
measured). Shared helper: `scripts/kaggle_common.py`.

## The inference notebook

`notebooks/kaggle_inference.ipynb` is generated by `scripts/package_kaggle.py` (do not edit it
by hand). The settings cell has one variable that picks the pipeline: `CONFIG =
"<name>"` (`configs/<name>.yaml` from the code dataset). The notebook:

1. finds `test.parquet`; installs RDKit from the wheel dataset (and any `WHEEL_DATASETS`);
2. puts the code dataset on `sys.path` and `PYTHONPATH` (worker processes);
3. builds `/kaggle/working/casmi_run/artefacts/` with symlinks to the artefact datasets plus a
   writable `processed/cache/` (mkey cache), and sets `CASMI_ROOT=/kaggle/working/casmi_run`,
   `CASMI_ARTEFACTS`, `CASMI_RAW` (the competition dir), `CASMI_CONFIGS`,
   `NUMBA_CACHE_DIR=/kaggle/working/numba_cache`;
4. runs `casmi.pipeline.run(io.read_test(test), cfg)` (per-molecule fallback inside), writes
   `/kaggle/working/submission.csv` with `io.write_submission`, then `io.validate_submission`;
5. if setup, the pipeline or validation raises, writes a valid fallback file (one guess per
   test molecule), so the run never ends without a submission; removes the symlink tree.

## Commands

Publish a new dataset version (same command creates the dataset the first time):

```
python scripts/kaggle_publish.py --name casmi-code --src src/casmi=casmi --src configs=configs \
    --src pyproject.toml --message "code at $(git rev-parse --short HEAD)"
python scripts/kaggle_publish.py --name casmi-db-np --src data/processed/db/np --message "..."
python scripts/kaggle_publish.py --name casmi-db-pubchem --src data/processed/db/pubchem --message "..."
```

Regenerate and push the notebook for a config, wait, download the output:

```
python scripts/package_kaggle.py push --config b0_npdb --wait --fetch
# prints "pushed /code/ograhulrajkumar/casmi-inference version N"; output lands in
# dist/kaggle/output/casmi-inference_vN/ (submission.csv, casmi-inference.log)
```

Push the code dataset first whenever `src/casmi` or `configs/` changed: the kernel mounts the
latest dataset version at push time and keeps it for the submission rerun.

Submit (always check first; the script refuses inside 55 minutes of the last submission or at
5 per UTC day and prints the seconds to wait):

```
python scripts/kaggle_submit.py --check
python scripts/kaggle_submit.py --kernel casmi-inference --version N --config b0_npdb \
    --local-score n/a --message "b0 NP-tier prior"
python scripts/kaggle_submit.py --status --wait   # fills the public score into docs/SUBMISSIONS.md
```

The submit call is `CompetitionApiService/CreateCodeSubmission` (competitionName, kernelOwner,
kernelSlug, kernelVersion, fileName `submission.csv`, submissionDescription), the call behind
`kaggle competitions submit -k OWNER/KERNEL -v N` in the 2.x CLI.

Environment probe (rerun when the Kaggle image may have changed):

```
python scripts/package_kaggle.py probe   # log text in dist/kaggle/output/casmi-probe_vN/
```

## GPU training kernel: contrastive encoder (RESEARCH.md roadmap item 1)

`scripts/kaggle_encoder_kernel.py` generates `notebooks/kaggle_train_encoder.ipynb` and pushes
it as the PRIVATE kernel `ograhulrajkumar/casmi-encoder-train` (GPU on, internet off). It
builds its own `SaveKernel` body because it needs `machineShape`: `NvidiaTeslaT4` gives the
"GPU T4 x2" machine (measured: 2 x Tesla T4, torch 2.11.0+cu130, CUDA 13.0, 4 CPUs). Mounted
datasets: `casmi-encoder-code` (src/casmi + scripts/train_encoder.py), `casmi-encoder-bundle`
(the training bundle), `casmi-db-np` (np_fp.npy) and `metric/rdkit-2026-3-3-wheel`. With two
GPUs the arms train in parallel, one subprocess per GPU (`CUDA_VISIBLE_DEVICES`), each for
`--hours`; with one GPU they run one after the other with hours / n_arms each. Outputs per arm
under `/kaggle/working/encoder/<arm>/`: `encoder_<arm>.pt`, `train_log.csv`, `eval.jsonl`,
`summary.json`, `stdout.log` (the optimiser checkpoint is deleted after export).

```
python scripts/kaggle_publish.py --name casmi-encoder-code --src src/casmi=casmi \
    --src scripts/train_encoder.py=scripts --message "..."      # whenever the code changed
python scripts/kaggle_encoder_kernel.py push --arms bce focal_con --hours 4.5 --timeout-hours 6
python scripts/kaggle_encoder_kernel.py status
python scripts/kaggle_encoder_kernel.py fetch    # -> dist/kaggle/output/casmi-encoder-train_<stamp>/
```

Notes: wait until the new code dataset version is READY before pushing (the kernel mounts the
latest version at push time). The running kernel exposes no partial log through
`ListKernelSessionOutput`; progress is only visible after completion. Throughput (smoke run
v1, 6 layers x 512, 150 tokens, batch 256, fp16 autocast): about 0.53 s per step for the BCE
arm and 0.57 s for the contrastive arm with 48 negatives, i.e. about 470 queries/s per T4.
